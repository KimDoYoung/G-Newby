## ⚙️ 실행 방법 (CachyOS 기준)

### 방법 1: Ollama (가장 간편)
```bash
# AUR 에서 ollama 설치 (CachyOS)
paru -S ollama

# Qwen3.5-9B 실행 (자동 Q4 양자화)
ollama run qwen3.5:9b

# 더 긴 컨텍스트 필요시
ollama run qwen3.5:9b --num_ctx 32768
```

### 방법 2: llama.cpp + GGUF (최대 제어)
```bash
# 의존성 설치
sudo pacman -S cuda cmake git base-devel

# llama.cpp 빌드 (CUDA 지원)
git clone https://github.com/ggerganov/llama.cpp
cd llama.cpp && make LLAMA_CUDA=1

# HuggingFace 에서 모델 다운로드
# 추천: "Qwen3.5-9B-Instruct-GGUF" 중 `Q4_K_M.gguf` 파일

# 실행 예시
./main -m ./models/qwen3.5-9b-q4_k_m.gguf \
       -n 512 -p "안녕, 한국어로 답변해줘" \
       -ngl 35 -c 32768
```

### 방법 3: LM Studio / KoboldCpp (GUI 선호시)
- CachyOS 에서 Flatpak 또는 AppImage 로 실행 가능
- GGUF 모델 드래그 앤 드롭으로 즉시 로드

## 💡 최적화 팁

1. **양자화 포맷 선택**
   - `Q4_K_M`: 품질/속도 균형 최적 [[19]]
   - `Q5_K_M`: 약간 더 좋은 품질, +1~2GB VRAM
   - `Q3_K_L`: VRAM 절약형, 품질 약간 하락

2. **GPU 레이어 오프로딩 (`-ngl`)**
   - 16GB VRAM 이면 9B 모델 기준 `-ngl 35~40` 추천
   - 나머지 레이어는 64GB RAM 에서 처리 → 속도 약간 저하 but 실행 가능

3. **컨텍스트 길이 관리**
   - 기본 8192 로 시작, 필요시 32768 로 확장
   - 너무 길게 설정하면 생성 속도 저하

4. **CachyOS 특화 최적화**
   - `cachyos-kernel` 사용 시 CPU 스케줄링 이점
   - `nvidia-dkms` 대신 `nvidia-ck` 커널 모듈 사용 권장 (AUR)

> 💬 **결론**: 우선 `ollama run qwen3.5:9b` 로 시작하시고, 더 높은 품질이 필요하면 llama.cpp 로 넘어가서 `-ngl` 과 양자화 옵션을 세밀하게 조정하시는 것을 추천드립니다. 64GB RAM 이 있으니 CPU 오프로딩으로도 충분히 유연하게 운영 가능합니다.

추가로 특정 사용 사례 (코딩 보조, 문서 요약, 한국어 챗봇 등) 가 있으시면 더 맞춤형 설정을 안내해 드릴 수 있습니다! 😊

죄송합니다. 확인 결과 **Qwen3.5-9B 는 Ollama 에 공식적으로 등록되어 있으며**, 사용자님의 환경에서 충분히 실행 가능한 모델이 맞습니다. [[11]]

기존에 사용 중이신 `qwen2.5-coder:14b` 와 비교하여 **Qwen3.5-9B 로의 전환이 더 나은 선택인지**, 그리고 **실행 방법**을 정리해 드립니다.

### ⚔️ `qwen2.5-coder:14b` vs `qwen3.5:9b` 비교

| 구분 | `qwen2.5-coder:14b` (현재) | `qwen3.5:9b` (최신) |
|------|-----------------------------|---------------------|
| **모델 아키텍처** | 이전 세대 (Qwen2.5) | **최신 세대 (Qwen3.5)** [[11]] |
| **파라미터** | 14B (더 큼) | 9.65B (가벼움) [[11]] |
| **VRAM 점유 (Q4)** | 약 8.5~9.0 GB | **약 6.6 GB** (여유 확보) [[11]] |
| **주력 특화** | **코드 생성/디버깅** 특화 | **범용 추론, 한국어, 멀티모달**, 코딩도 포함 |
| **응답 속도** | 상대적으로 느림 | **약 30~40% 빠름** (파라미터 감소) |
| **한국어 성능** | 우수 | **더 자연스럽고 문맥 이해도 향상** |

### 🎯 결론: 바꿔야 할까요?

**✅ 바꾸시는 것을 강력히 추천합니다.**

1.  **성능 세대 차이**: 파라미터 수는 작아졌지만 (14B→9B), 아키텍처가 최신인 **Qwen3.5 가 논리력, 코딩, 언어 이해도 전반에서 더 높은 효율**을 보입니다.
2.  **하드웨어 최적화**: 16GB VRAM 에서 6.6GB 만 점유하므로, **나머지 9GB 를 긴 컨텍스트(32K~128K) 처리**에 여유 있게 쓸 수 있습니다. [[11]]
3.  **리스크 없음**: 기존 모델은 삭제되지 않고 남아있으니, 새 모델을 먼저 테스트해 보고 마음에 들지 않으면 언제든 복귀 가능합니다.

> 💡 **단, 예외**: "레거시 코드 리팩토링"이나 "매우 특화된 프레임워크 코드 생성"만 매일 하신다면, 해당 도메인에 과적합된 14B 코더 모델이 여전히 유리할 수 있습니다. 하지만 일반적인 개발 보조 + 일상 업무 병용이라면 3.5-9B 가 훨씬 만족도가 높습니다.
