## Continue 설치 후 테스트 목록

---

## 0. 설치 확인 (15분)

```bash
# 터미널에서 먼저 확인
ollama list                    # qwen2.5-coder:14b 있는지
ollama run qwen2.5-coder:14b "안녕, 한국어로 답해줘"  # 기본 동작 확인
```

- [ ] VS Code에서 Continue 확장 설치
- [ ] `~/.continue/config.json` 에 Ollama + qwen 연결
- [ ] Continue 채팅창에서 "안녕"이라고 쳐서 응답 오는지 확인

---

## 1. 기본 한국어 소통 테스트 (10분)

```
GXT의 Grid에서 RowExpander를 사용하는 방법을 한국어로 설명해줘
```

**확인 포인트:**

- 한국어로 답하는지
- 답변 품질이 납득할 만한지
- 응답 속도가 답답하지 않은지

---

## 2. 파일 컨텍스트 테스트 (20분)

AssetERP에서 가장 단순한 CRUD 페이지 파일 1개를 열고:

```
# Continue 채팅에서
@현재파일명  이 코드가 어떤 역할을 하는지 설명해줘
```

그 다음:

```
@현재파일명  이 코드에서 버그가 있을 만한 부분을 찾아줘
```

**확인 포인트:**

- 파일 내용을 실제로 읽고 답하는지
- GXT 코드를 이해하는지

---

## 3. 코드 생성 핵심 테스트 (30분)

패턴 파일 2~3개를 열어두고 가장 중요한 테스트:

```
@파일A @파일B 를 참고해서 
다음 요구사항으로 새 GXT Grid CRUD 페이지를 만들어줘.

- 엔티티: [AssetERP에 없는 간단한 것 1개]
- 필드: 코드, 명칭, 사용여부
- 조회조건: 명칭
- 패턴은 @파일A 와 동일하게
```

**확인 포인트:**

- 기존 패턴을 따르는지, 아니면 멋대로 만드는지
- import 문, 패키지명이 맞는지
- 바로 쓸 수 있는 수준인지 vs 많이 고쳐야 하는지

---

## 4. MyBatis 생성 테스트 (20분)

```
@기존Mapper.xml 을 참고해서
AssetCategory 테이블의 CRUD Mapper XML을 만들어줘.
테이블 컬럼: CATEGORY_ID, CATEGORY_NM, PARENT_ID, USE_YN
```

**확인 포인트:**

- 네이밍 컨벤션이 기존과 일치하는지
- resultMap, namespace 패턴이 맞는지

---

## 5. @codebase RAG 테스트 (30분)

```bash
# 먼저 임베딩 모델 설치
ollama pull nomic-embed-text
```

config.json에 embeddingsProvider 추가 후:

```
@codebase GXT Grid에서 페이징 처리를 어떻게 하고 있어?
```

```
@codebase MyBatis에서 동적 쿼리 조건은 어떤 패턴으로 쓰고 있어?
```

**확인 포인트:**

- 실제 프로젝트 코드에서 찾아서 답하는지
- 엉뚱한 파일을 참조하지는 않는지
